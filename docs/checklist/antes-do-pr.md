# Antes de abrir o PR

Sempre, antes do push. [Voltar ao índice](../checklist-perguntas.md)

- Reli o meu próprio diff inteiro?
- O PR faz uma coisa só e tem um tamanho revisável?
- A descrição explica o porquê, como testar e onde o revisor deve prestar mais atenção?
- Removi `console.log`, código comentado, TODO sem tarefa e arquivos que não deveriam subir?
- Nomes de variáveis, funções e arquivos seguem as convenções do projeto (identificadores em inglês, textos em português)?
- Typecheck, testes e o pacote Android passam localmente?
- O commit segue o Conventional Commits do projeto, com uma linha por arquivo no corpo?
- Um colega que não participou entenderia esse código daqui a seis meses?
- A seção **Checklist** do PR traz as respostas que importam e os N/A que não são óbvios?
